# تحليل الطلب على الوجبات

تحليل استكشافي للطلب الأسبوعي على الوجبات عبر مراكز التوصيل، مع دراسة ارتباط العروض الترويجية وفرق السعر بالطلب، ورصد الوجبات الأعلى تقلبًا.

> **تنبيه:** البيانات رصدية، لذا تصف النتائج ارتباطات ولا تثبت السببية.

## المشكلة والهدف

يحلل المشروع سجل الطلبات الأسبوعية للوجبات في مراكز التوصيل للإجابة عن الأسئلة التالية:

1. كيف يرتبط الترويج عبر البريد والظهور في الصفحة الرئيسية بعدد الطلبات؟
2. ما علاقة فرق السعر النسبي بين السعر الأساسي وسعر الدفع بالطلب؟
3. ما الوجبات الأكثر تقلبًا في الطلب الأسبوعي؟

الهدف هو تلخيص الأنماط التاريخية وتقديم مؤشرات تساعد على توجيه التحليل والتخطيط، لا إصدار استنتاجات سببية أو سياسات تشغيلية نهائية.

## النتائج الرئيسية

| النتيجة | الرقم |
| --- | --- |
| ارتبط الجمع بين البريد والظهور في الصفحة الرئيسية بزيادة تقديرية في الطلب | **244.07 طلبًا لكل سجل**؛ فاصل ثقة 95%: **221.30–266.84**؛ `p < 0.001` |
| ارتبط البريد وحده بزيادة في الطلب، والظهور في الصفحة وحده أيضًا | **+123.77** و**+97.28 طلبًا لكل سجل** على التوالي؛ `p < 0.001` لكل مقارنة |
| أعلى الوجبات تقلبًا أسبوعيًا | الوجبات **2444، 1971، 1445**؛ معاملات الاختلاف **1.205، 1.104، 1.093** |

هذه التقديرات ارتباطية. كما أن فرق السعر مؤشر محسوب من السعرين في البيانات، وليس حقل خصم موثقًا.

للتفاصيل والرسوم، راجع [تقرير العميل](reports/client_report/client_report.md).

## مساهمة المشروع

يجمع المشروع بين خطوات تحليلية وتوثيقية مترابطة:

- فحص بيانات الطلب والتحقق من المفتاح المنطقي للسجل `(week, center_id, meal_id)` والقيم المطلوبة.
- إثراء سجلات الطلب بخصائص الوجبات ومراكز التوصيل، مع التحقق من مطابقة المفاتيح وثبات عدد الصفوف.
- مقارنة الطلب بحسب حالة الترويج، وتحليل ارتباط فرق السعر النسبي بالطلب.
- قياس تقلب الطلب الأسبوعي حسب الوجبة، ثم تلخيص النتائج في تقرير ورسوم.
- توثيق افتراضات التحليل وحدوده لتسهيل المراجعة وإعادة التشغيل.

## استخدام الذكاء الاصطناعي

استُخدم الذكاء الاصطناعي مساعدًا في استكشاف بنية البيانات، وتنظيم خطوات التحليل، وإعداد صياغة التقرير والتوثيق. أما أرقام النتائج فينبغي ربطها بمخرجات التحليل ومراجعتها؛ ولا يُعد استخدام الذكاء الاصطناعي بديلًا عن التحقق من البيانات أو عن التقييم البشري
قمت باستخدام visual studio code Copilot.

## البيانات والمنهجية

توجد ملفات البيانات المصدرية في `data/row/`:

- `train.csv`: بيانات التدريب ويحتوي على `num_orders`.
- `test.csv`: بيانات الاختبار ولا يحتوي على المتغير المستهدف.
- `meal_info.csv`: التصنيف والمطبخ لكل وجبة.
- `fulfilment_center_info.csv`: خصائص مراكز التوصيل.

يمثل كل سجل وجبة واحدة في مركز واحد خلال أسبوع واحد. التحليل الترويجي يقارن سجلات العرض بغير العرض بعد مراعاة أزواج المركز والوجبة وتأثيرات الأسبوع في النموذج المستخدم. يُحسب فرق السعر النسبي كما يلي:

```text
(base_price - checkout_price) / base_price
```

القيمة الموجبة تعني أن سعر الدفع أقل من السعر الأساسي، لكنها لا تثبت أن الفرق خصمًا تجاريًا. ويُحسب معامل الاختلاف لتقلب الوجبة على أنه الانحراف المعياري للطلب الأسبوعي مقسومًا على متوسطه.

## التشغيل

### المتطلبات

- Python 3.10 أو أحدث.
- Jupyter وملفات المشروع ومكتبات التحليل: `pandas` و`numpy` و`matplotlib`.

ثبّت المتطلبات عند الحاجة:

```powershell
python -m pip install pandas numpy matplotlib jupyter
```

### تشغيل دفتر التحليل

من مجلد المشروع، شغّل Jupyter:

```powershell
python -m jupyter lab
```

افتح [دفتر التحليل](notebooks/analysis.ipynb) وشغّل الخلايا بالترتيب. يعتمد الدفتر على وجود ملفات CSV في `data/row/`، ولا ينبغي تعديل ملفات المصدر أثناء التحليل.

## الحدود

- البيانات تحتوي على أرقام أسابيع، لا تواريخ تقويمية حقيقية؛ لذلك لا يمكن ربطها بشهور أو مواسم فعلية من هذه الملفات وحدها.
- المدينة والمنطقة ممثلتان برموز في بيانات المراكز، وليستا أسماء مواقع قابلة للتفسير المباشر.
- الارتباط لا يثبت السبب؛ قد تتداخل العروض مع فرق السعر وعوامل أخرى مثل توافر الوجبة.
- فرق السعر النسبي مؤشر استكشافي، وليس خصمًا موثقًا، كما أن العملة غير محددة.
- لا يحتوي ملف الاختبار على `num_orders`؛ لذلك لا تمثل نتائجه طلبًا فعليًا للأسابيع اللاحقة.
